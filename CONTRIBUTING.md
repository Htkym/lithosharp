# Contributing to PageSharp

Thanks for your interest in contributing. PageSharp is a small static site
generator for .NET, and contributions of all kinds are welcome: bug reports,
documentation, tests, and code.

## Getting started

You need the .NET 10 SDK (see [`global.json`](global.json) for the exact version).

```powershell
dotnet restore PageSharp.slnx --locked-mode
dotnet build PageSharp.slnx --no-restore -c Release
dotnet test --solution PageSharp.slnx --no-build -c Release
dotnet run --project samples/PageSharp.Sample -- --output _site
```

Running the sample is a quick end-to-end check: it depends only on the published
library surface, so it confirms the generator works without any private code.

## Conventions

- **Lock files.** `RestorePackagesWithLockFile` is enabled. When you change a
  dependency, restore and commit the updated `packages.lock.json` files.
- **EditorConfig.** Formatting is defined in [`.editorconfig`](.editorconfig)
  (LF line endings, UTF-8, final newline). Most editors apply it automatically.
- **Public API docs.** `GenerateDocumentationFile` is on. Write XML doc comments in
  English on public types and members so IntelliSense stays in English.
- **Tests.** Add or update tests under `tests/PageSharp.Tests` for behavior changes.
  Tests use TUnit on the Microsoft.Testing.Platform runner.

## Output-byte stability

PageSharp's generated output is consumed byte-for-byte by downstream sites. Changes
to templates, line endings, file encoding, or the target framework can shift the
generated bytes and affect those sites. When a change touches generation, run the
sample and review the diff in the generated site so the impact is intentional.

## Pull requests

1. Fork the repository and create a topic branch.
2. Keep changes focused; one logical change per pull request is easiest to review.
3. Make sure `build`, `test`, and the sample run succeed locally.
4. Describe what changed and why, and call out any change to generated output.
