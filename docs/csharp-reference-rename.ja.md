# C# 参照の名前変更プレビュー

カタログの再生成によって C# の静的メンバー名が変わる場合は、任意で Tool のコマンドを使えます。
元のカタログのメタデータと、検査する呼び出し側のソースファイルをすべて渡してください。
型には正確な CLR メタデータ名を使い、入れ子には `+` を含めます。

```sh
lithosharp preview-csharp-rename --source GuideLinks.cs --source Navigation.cs --reference old/Site.Catalog.dll --type Site.Guides+Pages --member Installation --new-name GettingStarted --define DOCS --format json
```

コマンドは厳密な UTF-8 のソースとメタデータイメージを読みます。
プロジェクトの評価、アセンブリの実行、ジェネレーターの実行、ソースの書き込みは行いません。
指定したメタデータから、Roslyn が一意の静的フィールド、プロパティ、メソッドを解決できる必要があります。
生成ファイルである `.g.cs`、`.g.i.cs`、`.generated.cs`、および先頭に `<auto-generated>` マーカーがあるファイルは除外します。
ソースの宣言は変更しません。

選択したメンバーにバインドされた使用箇所だけを編集対象にします。
バインドを証明できる場合は、修飾したアクセス、`nameof`、別名、static インポートを対象にできます。
同じ綴りでも、無関係なメンバーはそのままにします。
曖昧なバインド、別のシンボルを参照するようになる非修飾名、匿名オブジェクトやタプルの推論される名前には、手動の確認が必要です。
文字列、リフレクション、コメント、文書内の参照は、この対応範囲に含みません。

JSON は、正確なソースと明示的なメタデータの SHA-256、C# 13 の解析オプション、定義したシンボル、
null 許容の文脈、暗黙のランタイムフレームワーク参照、コンパイルエラー、手動確認の範囲を記録します。
各置換には、元の UTF-16 の開始位置と長さ、期待する元の文字列、内容のバージョン `sha256:<hash>` を含めます。
BOM と CRLF は位置に含まれ、返すバッファーにも保持されます。
このバージョンは取得したファイルの内容を識別します。LSP の文書バージョンではありません。

利用側はプレビューを適用する前に、取得したソースとメタデータのハッシュを**すべて**検証し、期待する各文字列も照合する必要があります。
入力が変わると、プレビュー全体が無効になります。
内部アダプターも同じ規則に従い、ファイルを書き込まずに変更後のバッファーを返します。
変更を受け入れる前に、バッファーをレビューし、元の入力からカタログを再生成し、名前変更後のメタデータでコンパイルしてください。
プレビューだけでは、新しいメタデータの契約を証明しません。

`coverage` は `Partial` のままです。
省略したソースファイル、別の条件付きコンパイル構成、後続の依存先、カタログの再生成は、明示的に残る作業です。
終了コード 0 は、確認できる保護付きの置換が一つ以上あることを意味します。
1 は適用可能なプレビューなし、2 は不正な使用方法、130 はキャンセルです。
証明できた一部の範囲が利用できる場合も、入力・コンパイラーの問題と手動確認の範囲を表示します。
