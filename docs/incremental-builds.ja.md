# 差分ビルド

`SiteGenerationOptions.BuildCacheDirectory` はビルドキャッシュの場所を指定します。`null` の場合は出力ディレクトリの隣にある `.lithosharp` を使い、出力の識別子ごとに分けて保存します。キャッシュは出力ディレクトリの外に置いてください。

`MaxDegreeOfParallelism` の既定値は `1` です。拡張機能は既定では直列実行され、コンテンツコレクションが `IsThreadSafe` を設定した場合だけページを並列化できます。レンダラーをキャッシュ可能にするには、明示的な `RendererFingerprint` も必要です。LithoSharp は fingerprint にレンダラーの実際のアセンブリとメソッド識別子を加えます。出力に影響する捕捉設定、テンプレート、その他の動作は fingerprint またはビルド入力に含めてください。

ソースコレクションの `IsCacheable` と、レンダラーのフィンガープリントの両方が必要です。型付きレンダラーはビルド時刻を参照できるため、時刻が変わるとソースが同じでも再生成します。変更のないページの描画を省略するには、同じ `BuildTimestamp` または `SOURCE_DATE_EPOCH` を指定してください。`DateTime.UtcNow` などの未宣言の値を読むレンダラーはキャッシュ可能と宣言しないでください。`clean: true` は常に再実行します。

`clean: false` では、ノードのキー、成果物の宣言、ステージング内のファイル、必要な描画済み本文を検証してから再利用します。破損・欠落・不一致があれば再生成します。削除の判断には既存の所有情報だけを使います。先に変更不能なキャッシュ記録を保存し、そのハッシュを出力マニフェストに記載して、既存の出力トランザクションで確定します。失敗したビルドは以前の出力と参照先を保持します。通常の更新は既存出力をステージングへ複製して検証しますが、全成果物を検証できた変更がないビルドでは公開済みの出力を直接検証し、複製を省略できます。

`SiteBuildReport.Nodes` の各ノードには `CacheHit` と `CacheMissReason` があり、レポートには `CacheHitCount` と `CacheMissCount` があります。生成・省略した成果物の一覧から、今回の実行と再利用を区別できます。互換性のため、`GeneratedFiles` は公開したすべての成果物を返します。依存関係が不明な旧テンプレートはページをキャッシュせず毎回描画します。明示した画像変換のキャッシュ契約には、入力バイト列、処理設定、実装の識別情報、出力メタデータを含めます。メタデータが欠落する場合や互換性がない場合は再生成します。Core はフォントの探索や暗黙のソーシャル画像処理を行いません。

資産変換はページの計画より前にハッシュ付きの出力ルートを確定します。変換キャッシュは従来どおり `AssetCacheDirectory` で指定し、`null` なら使いません。変換が実行された場合は、以前と同じバイト列でもミスとして報告します。変換キャッシュが使える場合も入力検証は実行します。任意のキャッシュ書込みに失敗しても、現在の生成はメモリ内の結果を使って続行します。出力への書込みに失敗した場合は生成を中止し、以前の出力を保持します。キャッシュ記録は出力の外に蓄積されます。使用量の確認と削除は `SiteGenerator.MeasureCache` / `ClearCache` または `lithosharp cache info|clean -o <directory>` で行います。どちらも出力ごとのロックを使うため、生成中の同じキャッシュ区画を並行して確認・削除しません。MDX ブリッジは次回の準備時に1日以上経過したワーカーの一時ファイルと書込み途中のファイルも削除します。

## Markdown の解析キャッシュと診断

Markdown の解析結果とページの描画結果は別に再利用します。解析キャッシュはコンパイラーのフィンガープリントと本文の厳密なハッシュで識別し、本文の長さ、記録形式、内容と整合性も検証します。コンパイラーの識別には実装のバージョン、CommonMark／GFM 仕様のバージョン、Syntamark パーサーのバージョンと実行時モジュール識別子、解析設定、構文・出力プロファイルを含めます。ライブラリだけを更新した場合も、以前の解析結果を無条件には使いません。不正な UTF-16 と置換文字を含む有効な本文は別の入力として扱います。

解析キャッシュはレイアウトに依存しない HTML と意味情報を保持します。見出しの調整や外部リンク属性など、サイト設定に依存する後処理は生成ごとに適用します。診断またはコンポーネントを含む解析結果は、この永続解析キャッシュには保存しません。`clean: true` は各ノードを再実行しますが、検証済みの解析キャッシュまで無効にする指定ではありません。

一度の実行時の読み込み・ビルドで元の本文解析を保持できるのは、テキスト、ソースの識別情報、パーサー、プロファイル、オプション、要求した解析項目がすべて一致する場合だけです。
コードの取り込みなどで本文を変換した場合は、変換後の本文を解析します。
大きい上限で行った変換前本文の警告解析は、厳密な最終本文の解析結果とは扱いません。
入力やリソースの上限による失敗はエラーの根拠として保持し、公開を停止します。正常な空の解析結果ではありません。
コンパイラー、エディター、ビルドは別々のホストであり、プロセス間でASTを共有しません。

型付きコレクションのページでは描画時の Markdown 診断をページのキャッシュ記録に保存します。検証済みのヒットではレンダラーを呼ばずに診断を復元するため、警告が消えることはありません。「診断がないと確認済み」と「診断結果が不明」は区別し、診断記録が欠けていれば再描画します。記録が破損している場合や形式が合わない場合も再生成します。

ローダーが保持した解析と実際に描画する本文が一致する場合は、元ファイルの行・列を維持できます。本文を変換した場合は解析し直し、対応が確認できない元の行・列を付けません。生成ページなどに元ファイルがなければ、ソース位置は省略します。解析が不完全な場合は品質検証エラーとなり、公開済みの出力とキャッシュの参照先を保持します。

必要な解析情報だけを選ぶ操作は、ネイティブの増分セッションとは別です。
エディターでは文書のセッションと変換後本文のセッションについて、ソースとオプションの識別情報を分けて保持します。
編集を順番に適用し、古い世代の結果は破棄します。
ヘッダー専用の走査はヘッダーの境界を確認するもので、本文の妥当性を証明しません。
同様に、最終 HTML の解析情報のキャッシュは、サイト全体の品質判定のキャッシュではありません。
リンクとルートは現在のビルドに対して検査します。
[型付き Markdown の読み込み](typed-markdown-collections.ja.md#コードの取り込みと本文解析)と[サイト品質](site-quality.ja.md)を参照してください。

ソースマップの根拠があれば、変換後の Markdown や取り込んだコードを元のファイルへ対応付け、取り込みのディレクティブを関連位置に保持できます。
正確な対応やトークンを覆う対応は、部分的または不明な対応と区別します。
対応を確認できない場合は、元の行・列を割り当てません。

## 型付きページの設定例

次の例では、`articles` は `isCacheable: true` で読み込んだ `ContentCollection<ArticleFrontMatter, string>`、`ArticleLayout` は `IPageLayout<ContentEntry<ArticleFrontMatter, string>>` の実装です。

```csharp
var collection = new SiteContentCollection<ArticleFrontMatter, string>(articles, new ArticleLayout())
{
    RendererFingerprint = "article-layout:v1", // Include captured configuration here.
    IsThreadSafe = true
};
var options = new SiteGenerationOptions
{
    ContentCollections = [collection],
    BuildTimestamp = DateTimeOffset.Parse("2026-09-02T00:00:00Z"),
    MaxDegreeOfParallelism = 4
};
var result = await new SiteGenerator().GenerateWithOptionsAsync(
    site, posts, output, clean: false, customization, options, cancellationToken);
```
