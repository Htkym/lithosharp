# C# reference rename preview

Use the opt-in Tool command when a regenerated catalog will rename a static C#
member. Supply the original catalog metadata and every caller source file you want
inspected. The type uses its exact CLR metadata name, including `+` for nesting.

```sh
lithosharp preview-csharp-rename --source GuideLinks.cs --source Navigation.cs --reference old/Site.Catalog.dll --type Site.Guides+Pages --member Installation --new-name GettingStarted --define DOCS --format json
```

The command reads strict UTF-8 source and metadata images. It never evaluates a
project, executes an assembly, runs a generator, or writes source. Roslyn must
resolve a unique static field, property, or method in the supplied metadata.
Generated files (`.g.cs`, `.g.i.cs`, `.generated.cs`, and a leading
`<auto-generated>` marker) are excluded. Source declarations remain untouched.

Only usages bound to the selected member produce edits. Qualified access,
`nameof`, aliases, and static imports are eligible when their binding is proved.
Unrelated members with the same spelling are retained. Ambiguous bindings,
unqualified names that would capture another symbol, and inferred anonymous
object or tuple names require manual review. Strings, reflection, comments, and
documentation references are outside this subset.

JSON records the exact source and explicit metadata SHA-256 byte hashes, C# 13
parse options, defined symbols, nullable context, implicit runtime framework
references, compiler errors, and manual scopes. Each replacement contains its
original UTF-16 start and length, expected original text, and a content version
(`sha256:<hash>`). BOMs and CRLFs contribute to these offsets and remain in the
returned buffers. This version identifies the captured file contents; it is not
an LSP document version.

A consumer must validate **all** captured source and metadata hashes and every
expected string before applying the preview. Changed input invalidates the
entire preview. The internal adapter follows the same rule and returns changed
buffers without writing files. Review the buffers, regenerate the catalog from
its source input, and compile against the renamed metadata before accepting the
change. The preview alone does not prove the new metadata contract.

`coverage` remains `Partial`: omitted source files, other conditional compilation
configurations, downstream dependencies, and the catalog regeneration remain
explicit work. An exit code of 0 means at least one guarded replacement is
available for review. Exit 1 means no applicable preview; exit 2 means invalid
usage, and exit 130 means cancellation. Input/compiler issues and manual scopes
remain visible even when a proven subset is available.
