# Markdown プロファイル

生成オプションで、正確な Markdown プロファイルを選びます。
フロントマターのバインド、公開ルール、OKF の適合性は、別の設定です。

```csharp
var options = new SiteGenerationOptions
{
    Markdown = new MarkdownOptions
    {
        ProfileId = MarkdownOptions.DocumentationProfile,
    },
};
```

`MarkdownOptions` は `LithoSharp.Content` にあります。対応するプロファイル ID は次のとおりです。

| プロファイル | 動作 |
|---|---|
| `lithosharp-markdown/1` | 既存の LithoSharp の構文と見出しの表示です。引き続き既定値です。脚注の表記はリテラルのままで、既存の `LIT001` 助言を出します。 |
| `commonmark/0.31.2` | HTML トークンの境界も含め、CommonMark として解釈します。GFM テーブル、数式、構造化ディレクティブなどの文書用拡張は有効にしません。認識した HTML は表示用にエンコードし、生の HTML として実行しません。 |
| `syntamark-docs/2` | ネイティブの脚注と構造化ディレクティブを含む文書用構文です。型付きコンポーネントには、さらに明示的な登録が必要です。 |

どのプロファイルも、コンテンツローダーが YAML ヘッダーを分離した後の Markdown 本文を受け取ります。
本文の先頭にある `---` は本文の構文であり、別のヘッダーではありません。
単独の文書に対する CommonMark パーサーの扱いは、型付きコンテンツローダーのフロントマターの要件を変えません。

文書用プロファイルは最初に参照した順番で脚注に番号を付けます。
同じ脚注への各参照にはそれぞれ戻るリンクがあります。生成 ID は見出し ID と衝突しないようにします。
同じラベルの最初の定義を使い、重複には `LMD030` を出します。
未解決の参照はリテラルのままにし、`LMD031` を出します。
参照しない定義と、重複した定義の本文は表示しません。
コードフェンスとインラインコードでは、元の表記を維持します。
リンクのラベル内に脚注マーカーがある場合は、入れ子のアンカーを避けるため、移動できるマーカーをそのリンクの直後に表示します。

定義リスト、汎用属性、グリッドテーブルは引き続き未対応です。
構文候補の検出や、任意の互換性の助言によって、それらの描画が有効になるわけではありません。

エディターから直接検査する場合は、同じオプションを渡します。

```csharp
var inspection = DocumentInspection.Inspect(path, unsavedText,
    new DocumentInspectionOptions { Markdown = options.Markdown });
```

取得したプロジェクトのスナップショットは、選択したプロファイルを言語サーバーに渡します。
プロファイルを変えると、ワークスペースが保持する結果と、サイトの永続的な Markdown キャッシュが無効になります。
登録したコンポーネントの実装を実行するのは、信頼した生成処理だけです。エディターの検査は静的メタデータを使います。

既存のサイトを移行する場合は、無関係な設定を変えている間は既定のプロファイルを維持します。
その後で新しいプロファイルを選び、生成した見出しの文字列、アンカー、テーブル、HTML リテラル、脚注を確認してください。
公開前に、公開時点の基準との比較で、失われた URL やアンカーを確認します。ビルドの成功は基準を更新しません。
