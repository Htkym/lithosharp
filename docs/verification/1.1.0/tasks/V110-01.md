## 何をしたか

以後の「直った」「速くなった」を同じ手順で判定できるよう、fixtureの分類、変更scenarioの期待値、実行evidence記録runnerを追加した。既存テストを複製せず、実在するfixtureとテストを指す形にした。

| 追加物 | 役割 |
| --- | --- |
| `eng/Invoke-V110Verification.ps1` | 4つのaction（`run` / `manifest` / `compare` / `self-test`）を持つ実行・記録・比較runner |
| `eng/verification/1.1.0/fixtures.json` | 18 fixtureの分類（markdown-only / mdx / typed-collection / blog / docs / version-locale / migration / inspection / multi-project / sample）と提供元テスト |
| `eng/verification/1.1.0/scenarios.json` | 18 scenarioの期待（成果物、無効化集合、parse/render/bundle対象、診断、旧出力保持）と既存coverage・gap |
| `eng/verification/1.1.0/commands/v110-01-baseline.json` | runner自身を実commandで検証するためのcommand file |

runnerの方針：

- command配列・cwd・timeout・許容exit code・env上書きをstep単位で受け取り、exit code、所要時間、stdout/stderrのファイルとSHA-256、fixtureのtree hash、outputのtree hash、env差分のfingerprintを保存する。ログの最終行では成否を決めない。
- timeout時は所有process treeを停止し、statusを `timeout` として残す。
- 期待値の自動上書き機能を持たない（`compare` は実行前後でexpected manifestのSHA-256を照合し、変化があれば例外にする）。
- 除外する非決定的・派生物はpatternと理由をmanifestへ記録する（`node_modules`、`bin`、`obj`、`.git`、`.vs`、`.lithosharp`、`TestResults`、`artifacts`、`.tmp`）。
- 比較カテゴリは files（path集合とbyte hash）、routes、diagnostics（id/severity/line/column）、dom（呼出側が正規化した選択結果）、exitCode。HTMLの再解析はしない。
- 固定時計は比較対象のartifactに埋め込まない。site出力の比較では既存の明示timestamp APIを使い、runner自身の時刻は実行記録にだけ残す。
