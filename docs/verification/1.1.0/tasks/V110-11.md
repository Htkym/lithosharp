実施日：2026-09-27（日本時間）

証跡：`.local/verification/1.1.0/v110-11-20260927/`（build/test/Markdig比較/worker npmログ）

## 棚卸し（手順1）

- worker要求は`compile`の1種別のみで、analysis-only経路はなかった。
  全呼出しが前処理→`mdx-code-block`展開→MDX parse→意味抽出→module解決→compile/bundle→SSRを通る。
- `authoring` pluginが見出し・リンク・テキスト・fallback・islandを集め、
  `codeBlocks`がrehype-slugのidを戻す。importはesbuildの解決時に扱われ、静的宣言の抽出はなかった。
- workerは`MdxSite`所有の単一process＋gate直列で、取消・timeout時は所有treeごとkillする。
  位置は1-based行で端から端まで運ばれ、source mapは作らない（content hashのみ）。

## 実装

- `worker/compiler.mjs` に`analyzeMdx`を追加。buildと同じunwrap・MDX parser・許可構文変換
  （directive・math・slug・code metadata）を使い、見出し・リンク・テキスト・island・import宣言・診断だけを返す。
  `codeBlocks`はモジュールscopeへhoistしてbuildと共用し、挙動は不変。
  user plugin・component moduleの読込、importの解決・実行、bundle、SSR、`CodeBlock` sourceの
  ファイル読込、network取得は行わない（ファイル・process・network workなし）。
- `worker.mjs` は`analyze`型を受付。異常時は既存envelopeでLSMDX001診断を返し、workerは維持される。
- 新設 `src/LithoSharp.Mdx/MdxInspectionSession.cs`（Unshipped）：
  `MdxAnalysisOptions`（文書版数・project generation）、`MdxAnalysisResult`（題・テキスト・
  見出し・リンク・asset・component・import宣言・診断・stage=syntax）、`MdxImportInfo`。
  編集用の独立workerを所有し、build実行workerと取消・寿命を分離する。
  入力取消で利用者のbuildをkillしない。front matter分割・行対応はbuildと同じ模型で元bufferへ戻し、
  対応不能な位置は行精度（列null）にし、架空の列を作らない。
  構文未完成ではfatal診断のみでsymbolsは空にし、以前の正常symbolsを最新として返さない。
  Core→Mdxの新規参照はない。TypeScriptの型検査は行わない（workerはtranspileのみ）。
