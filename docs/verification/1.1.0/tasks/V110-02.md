### Generator host の判断

- 参照Roslyn版は `4.14.0`（1.0.0と同一）に固定した。理由は、(1) B0で検証済みの組み合わせである、(2) 固定SDK 10.0.300のcompiler 5.6.0.0より低い、(3) 追加SDK 10.0.108のcompiler 5.0.0.0でも読み込める（5.6.0へ上げると10.0.108では読めなくなる）。
- 5.9.0でしか使えないRoslyn APIは使用していない（`GeneratorTests` は `CSharpGeneratorDriver` / `AnalyzerConfigOptions` など4.x系APIのみ）。最低SDKの引き上げはしていない。
- 再発防止として `eng/Test-GeneratorHostCompatibility.ps1` をCIのBuild直後に実行する。CS9057の警告はビルドを止めないため、警告の有無ではなく参照版の比較で判定する。

## 未実施・未解決

- CIの実検証は未実施（workflow編集のみ。push・PRは計画の公開操作に含まれないため実行していない）。
- CIが使う最新SDK（10.0.401）のcompiler版は未測定。`eng/Test-GeneratorHostCompatibility.ps1` は実行時のSDKを読むため、CI上では実際に使われたSDKで判定される。ローカルで10.0.401を入れての確認は未実施。
- `Microsoft.CodeAnalysis.CSharp` の自動更新（Dependabot）が再びcompilerより新しい版を入れるとCS9057が戻る。CIのgateで検出するが、依存更新PRの受入条件としてV110-29の運用に引き継ぐ。
- 開発機のグローバルNuGet cacheに「.nupkgが無いLithoSharp 1.0.0フォルダ」がある状態では `dotnet pack` がMSB4018で落ちる。gate scriptは隔離 `NUGET_PACKAGES` を使うため影響を受けない。開発者向け注意としてV110-22の文書候補にする。
- overload追加時の曖昧性検証はconsumer fixture 1件のみ。1.1.0でoverloadを追加するタスク（V110-03/10/11）でfixtureを増やす。
