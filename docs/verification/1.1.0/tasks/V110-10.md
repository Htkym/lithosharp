## 棚卸し（手順1）

- 現`DocumentInspection.Inspect`はYAML構文解析（LSM001/002/003/004等）と本文解析（LIT001/002＋opt-in advisory）のみで、
  実buildのfront matter bindingやroute解決とは別物だった。未知field・型不一致・必須欠落は見えず、
  `Route`は呼び出し側指定のechoだった。本タスクでremarksに明記し、「全build診断と同等」とは説明しない。
- 実buildは`ReflectionContentFrontMatterBinder`でLSC101（未知）/102（null不可）/103（型不一致）/104（必須欠落）を出し、
  `PagePublicationPolicy`でdraft・期間・環境を除外してからcatalogへ載せる。routeはDocsが
  `prefix + (Slug ?? Id)`、Blogが`prefix + Slug`、typedがcaller規約で作り、拡張側がslugを推測しない。
  `ISiteBuildExtension.GetInspection()`は既に variants/pages を返し、Tool `inspect` はfull buildである。

## 実装

- 新設 `src/LithoSharp/Inspection/ProjectInspectionSnapshot.cs`（Unshipped）：
  `ProjectRouteCandidate`（sourcePath/publicPath/projectId/collection/version/locale/publication）、
  `ProjectInspectionSnapshot`（projectId/generation/Core version/collection/language/schema/version/locale/
  routes/acquiredAt、`Create`/`ToJson`/`ParseJson`）、`DocumentProjectStatus`
  （NoContext/Resolved/Ambiguous/Unresolved/Draft）。
- `DocumentInspectionOptions.Project`（既定null、加算）。contextなしでは従来どおり構文解析のみで、
  不足を成功として隠さない。実project評価の自動実行は足さず、取得済みsnapshotを入力として受けるだけ。
  起動直後・キー入力ごとのMSBuild/factory実行は行わない。
- route解決はsnapshot内候補の完全一致・接尾辞一致で、version/locale不一致は除外する。
  1件でResolved、複数でAmbiguous（Routeはnull、一件を選ばない）、0件でUnresolvedかDraft。
  draftはraw front matterの`draft: true`で判定し、Routeはnullにする。unlistedは候補の状態としてResolvedを維持する。
- front matter検証は組み込みschema（document/post）のみ実binderと同一情報源で実行し、ID/severity/位置を一致させる。
  custom schemaは束縛しない。利用者のconstructor/setter/validatorはキー入力ごとに実行しない。
- CLIは`markdown-compat --project <snapshot.json>`を同じ`Inspect`に接続する。
  JSON snapshotは未解決fieldをnull/明示statusで出し、`--project`なしの既存出力は変えない。
  snapshotの取得自体は明示操作（本タスクでは呼出側が構築し、factory駆動の取得はV110-14以降）。
