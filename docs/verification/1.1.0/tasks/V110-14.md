## 選定（手順1）

- transportは標準ライブラリのみ（`System.Text.Json`＋stdio）。
  7 method＋1通知のためにLSP library一式を依存に入れない判断を
  `docs/verification/1.1.0/contracts/lsp-transport.md` に記録した。
  framing全体の独自実装を目的にせず、Content-Lengthの送受信と再同期だけを持つ。
- LSP 3.17を基準とし、広告＝実装（textDocumentSync/incremental、documentSymbol、
  push診断、cancel、名前空間付きproject通知）に限定する。未実装capabilityは広告しない。

## 実装

- 新設 `src/LithoSharp.LanguageServer/`（net10.0、slnx配線）：
  `StdioTransport`（frame送受信・分割/連結・UTF-8 byte長・garbage再同期、stdout純度）、
  `LspServer`（dispatch・buffer・context・診断/symbols・取消・寿命）、`Program`（stdio駆動）。
- transportはstdioでContent-Length framingを使い、CLI JSON Linesと混同しない。
  stdoutはframeのみ、logはstderrへ集約する。
- initialize/initialized/shutdown/exit、didOpen/didChange/didSave/didClose、
  publishDiagnostics、documentSymbol、`$/cancelRequest`を実装する。
- position encodingはUTF-16を宣言し、incremental変更を順に適用する。
  不正rangeと逆行versionは安全に拒否・再同期し、異常入力でserverを落とさない。
- V110-12のqueueとsnapshotを使い、文書変更のたびにfull-site buildを呼ばない。
  project contextは明示の`lithosharp/projectContext`通知（V110-10 snapshot JSON）からのみ受け取り、
  reloadでgenerationを更新する。
- 診断位置のLSP変換は1か所で行う（Core 1-based UTF-16 → LSP 0-based）。
  文書外診断は出さず、存在しない文書の1行1列へ捏造しない。
- heading階層からDocumentSymbolを作り、selectionRangeとrangeには保有する正確な範囲を使う。
  未知の範囲を別解析で推定しない。
- serverのCore versionとcontextのCore versionのmajorを照合する。
  互換不明なproject assemblyを同一processへ動的ロードしない（contextはdataのみ）。
- 依存・Node不足、未解決project、worker異常は説明し、Markdown機能は維持する。
  shutdownで全所有sessionを破棄する。TypeScriptの型検査は行わない。
