## 実装したもの（no-op bypass）

未変更成果物を複製せず、公開中のtreeをその場で検証して再利用する。

1. `OutputTransaction.CreateAsync(..., deferExistingCopy)` でstagingへの複製を遅延。
   `MaterializeExistingOutputCopyAsync` が冪等に複製する（既定は従来どおり即時複製）。
   `ReadPreviousBuildCacheKeyAsync` は複製前なら公開中のmanifestを読む。
2. `ExecuteBuildAsync` の事前判定：`clean=false`、subsetでない、executed transformなし、
   `cachePolicy=always-rebuild` ノードなし、全ノードで key と artifact宣言が前回と一致、
   所有権状態にstaleがない（manifestを含む現在所有集合と比較）とき bypass。
   成立時は各artifactを公開treeから読み取り+hash検証し、失敗したら複製して通常のmiss経路へ戻す。
3. bypass時は manifest・所有権状態・commit・cache保存をスキップ（内容が同一のため）。
   品質検査の読み取りrootは公開tree、`GeneratedFiles` はplanのartifactから構築。
4. stale削除は複製の後（品質検査の直前）へ移動。複製前に実行すると、遅延複製で復活した
   staleファイルを消し損ねる（`AddDeleteRename_UpdatesArtifacts` が検出）。

## 未完了（次段）

### overlay commit の設計（確定）

本文1件変更で未変更の約1,008ファイルを複製しないための設計。実装は atomic publication の core を書き換えるため、専用セッションでテストと5 pair以上のA/Bを一続きで行う。

1. **前提を限定する（same-shape rebuild）**：現在の plan の artifact 集合と所有権状態の集合が一致し（stale も新規も無い）、`deferExistingCopy` の対象であるとき、staging には *miss ノードが書いた artifact だけ* を置く。cache-hit は公開treeでその場検証する（bypass と同じ検証経路）。
2. **commit をジャーナル化**：staging 上の各ファイルについて、公開側の既存ファイルを `_backupRoot` の同一相対パスへ移動し、staging のファイルを公開側へ移動する。全件成功したら backup を削除。途中失敗時は移動済みを逆順で戻し、staging の残りを破棄する（既存の rollback 思想を保つ）。
3. **manifest・所有権状態**：artifact 集合が同一なので、置換対象の hash だけを更新する。集合が変わる場合（stale 有り・新規有り）は従来の全体 staging + swap にフォールバックする。
4. **不足するもの**：`OutputLock` の registered backup への登録、`ApplyCopiedMetadata` 相当の timestamp/attribute 処理（置換対象のみ）、recovery（`RecoverRegisteredTransactionsAsync`）での overlay 中断の扱い。
5. **検証**：`SiteGeneratorAtomicOutputTests` 全件 + 新規「置換中失敗で全ファイルが元に戻る」「overlay 後に集合・hash・所有権が一致」「read-only 出力」「cancel」、そして 5 pair以上の交互A/B（期待: 本文1件の Transaction 2,079〜3,969ms → 0.1〜0.5s、公開tree検証の read+hash 分のみ）。
6. **採用しない代替案**：共有 hardlink（plan §2.5 が禁止。ACL/timestamp が同一 inode を共有するため、metadata 書込みで公開物を変更してしまう）。公開ファイルの一時退避（build 中に公開treeが不完全になり、serve 中の読者に欠落が見える）。
