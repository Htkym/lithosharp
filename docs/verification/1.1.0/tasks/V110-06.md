## 実装

### no-op bypass（未変更なし）

- `OutputTransaction.CreateAsync(..., deferExistingCopy)` で staging への複製を遅延。
  `MaterializeExistingOutputCopyAsync` が冪等に複製する（既定は従来どおり即時）。
  `ReadPreviousBuildCacheKeyAsync` は複製前なら公開中の manifest を読む。
- `ExecuteBuildAsync` の事前判定：`clean=false`、subset でない、executed transform なし、
  `cachePolicy=always-rebuild` ノードなし、全ノードの key と artifact 宣言が前回一致、
  所有権状態に stale なしのとき bypass。成立時は各 artifact を公開 tree でその場検証し、
  失敗したら複製して通常の miss 経路へ戻す。
- bypass 時は manifest・所有権状態・commit・cache 保存をスキップ（内容が同一のため）。
  品質検査の読み取り root は公開 tree、`GeneratedFiles` は plan の artifact から構築。

### 変更分 overlay（same-shape rebuild）

- 事前判定：所有権状態の集合と現在の所有集合（plan artifacts + manifest）が完全一致し、
  公開 tree が存在するとき overlay（`TryEnableOverlayCommit`）。stale や新規 artifact が
  ある場合は従来の全複製へフォールバックする。
- cache hit は公開 tree でその場検証（bypass と同じ検証経路）。miss の artifact だけが
  staging に書かれる（`BuildExecutionResult.StagedArtifacts` で caller へ伝える）。
- commit はジャーナル付きの per-file 置換（`CommitOverlayAsync`）：
  `backup/` に `.lithosharp-overlay-journal.json`（新規作成パス一覧）を書いてから、
  置換対象を backup へ退避 → staged を公開 tree へ移動。失敗時は逆順で復元し、
  成功時は journal → staging → backup の順に破棄する。
- 所有権状態は「前回 state の hash を残しつつ staged の hash を差し替える」方式で作る
  （`CreateOverlayArtifactStatesAsync`）。再 hash するのは staged 分だけになる。
- 中断復旧：journal が残る backup は「未 commit」とみなし、backup のファイルを公開 tree へ
  戻し、journal の created 一覧を削除する（staging に残っているものは未配置として温存）。
  既存の full-swap recovery より先に処理する。
- stale 削除は複製の後（品質検査の直前）へ移動。複製前に実行すると、遅延複製で復活した
  stale ファイルを消し損ねる（`AddDeleteRename_UpdatesArtifacts` が検出）。

（Transaction ≈16ms、commit 0、allocation ほぼ同等）で、前回セッションの測定
（4,320ms → 2,081ms）を維持している。before/after とも bypass が選ばれるため、
比較自体が「bypass 同士＋overlay コード」の対照になっている。

- 本文1件変更：Transaction 1,282〜15,929ms → 15〜57ms、commit 436〜974ms → 31〜51ms、
  allocation 299〜311MB → 120〜144MB（全5 pairで一貫、約58%減）。
- 残る支配コストは公開 tree の読み取り+hash 検証（Execution の一部、1,000頁で約0.6〜1.4s）。
  複製直後は page cache に載っていた検証が、公開 tree の読み出しになった分。それでも
  copy+swap より安い。
- 期待どおり no-op は bypass、本文1件変更は overlay が選ばれ、どちらも Transaction と
  commit が実質ゼロになった。
