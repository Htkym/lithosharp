## 実装

- `src/LithoSharp/Inspection/DocumentWorkspace.cs` を書き換え：
  - 文書キーはworkspace＋project＋URI（projectなしでは従来の文書識別子そのまま、URIの小文字化なし）。
  - 新設 `InspectVersionedAsync(sourcePath, text, documentVersion, projectGeneration, options?, ct)`：
    受理時に版数・世代を予約し、解析終了時に再照合してからsnapshotをcommitする。
    commitは世代が新しいか、同世代で版数が以上のときだけ行い、遅い旧要求の上書きはない。
  - CPU解析は寿命lockの外で実行し、lockは状態遷移とsnapshot交換に限定する。
    元テキストは不変の入力snapshotとして渡す。解析中も状態照会と停止が応答する。
  - 文書あたり最新pending要求だけを残す有界queue（旧pendingは取消）と、
    .NET解析の同時実行2件以内のslotを持つ。MDXはprojectあたりworker1件が
    `MdxInspectionSession`の所有構造で成立する（設定変更には資源測定を要するため固定）。
    キーストロークごとの無制限Task.Runはない。
  - 新しい編集で古い解析へ取消を通知するが、受け取り側でも世代を照合する。
    共有のentry取消sourceはworkspace破棄時にだけ破棄し、要求ごとのlinked sourceは要求終了時に破棄する。
  - close/remove/rename/reload/disposeでpendingを取消し世代を失効させる。
    遅延した旧要求の完了で削除文書が復活しない。renameは破棄と再検査で行う。
  - 同一版数・世代・本文の再要求は再解析せずcommit済みを返す（保存とwatchの二重通知対策）。
    disk版とbuffer版の切替は呼び出し側の版数で行う。
  - 破棄時はpending取消後に有界timeout（5秒）で終了を待ち、timeout時は待機を打ち切る。
    workspaceは所有processを持たない（MDX workerは呼び出し側のsession所有）。
    取得済みsnapshotは破棄後も不変のまま利用できる。
- 新設 `TryGet(projectId, documentId)` / `Remove(projectId, documentId)`（加算）。
  同URI別project・同名文書別workspaceの混線はない。
