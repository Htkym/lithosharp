## 棚卸し（手順1）

- 既存のstartup/rebuild-succeeded/rebuild-failed/startup-failed/shutdown JSON Linesと
  終了codeを整理し、text modeは維持する。stdoutはイベント、stderrは人間向けログに分離済みで、
  machine modeのstdout純度は既存テストが固定している。

## 実装

- 新設 `serve --control-stdin`（`--format json`必須、text併用はexit 2）。
  このoption時だけstdinのJSON Lines制御を受ける。初期commandは`shutdown`のみで、
  schema/versionとrequestIdを検査する。既定stdin動作は変えない。
- 停止は所有関係に沿って行う（watch停止→worker/host停止→HTTP停止→host終了）。
  rebuild中停止は進行中buildを中断してから畳む。二重shutdownはackのみで冪等、
  起動途中shutdownはserveを開始せずexit 0、rebuild中shutdownも単一shutdownでexit 0にする。
- stdin EOF・親controller終了も制御modeでは正常停止要求として扱う（exit 0）。
- 不正control messageは構造化error（control-error）として返す。入力全文や秘密値は返さない。
  stdout純度は`Assert-StdoutPure`で固定する。
- 実装上の注意：`Console.In`の非同期読取は呼出スレッドで同期待ちするため、
  stdinはmain flowが待たない専用worker threadで同期的 `ReadLine` する。
  終了時に待たず、完了済みの場合だけ回収する（process終了が回収する）。
- 世代識別：初期buildを1とし、完了したrebuildごとに世代を進める。
  startup/rebuild-succeeded/rebuild-failed/shutdownとdiagnostics endpointに載せる。
  失敗中は最後の成功outputを保持し、失敗の診断とは別に取得できる（既存動作を世代付きで固定）。
- base pathの区別：`basePath`（serve配信、現行root契約 `/` を維持）、
  `siteBasePath`（生成siteのBaseUrl path、`__host`経由で取得、未取得はnull）、
  source→route snapshot（startupの`routes`と`inspect`/`buildPlan`のartifact publicPath）。
  出力directory名からのURL推測や二重prefixは行わない（配置とURLの対応をfixtureで固定）。
