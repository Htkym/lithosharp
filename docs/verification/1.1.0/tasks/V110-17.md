## 実装

- `src/lspConnection.ts`：Content-Length送受信とid対応。応答順の逆転でも正しく対応付け、
  garbageでは落とさず再同期する。
- `src/lspClient.ts`：単一編集session。file-schemeのMarkdown/MDXだけを繋ぎ、
  言語IDと拡張子の組合せで判定する（他MDX拡張との二重serverなし）。
  didOpen/change/save/closeを最新版数付きで送り、変更は150ms（50〜1000ms可変）でdebounceする。
  未保存解析とbuild診断はEditor側collectionで版数管理し、古い版数を残さない。
  project context未取得などはStatus/Outputへ明示し、空Problemsを正常と表示しない。
  キー入力で全体build・SSR・利用者module実行は起きない。
- `src/diagnostics.ts`：版数guard付きcollection。close/delete/rename/project切替で消去し、
  遅延応答の再表示を防ぐ。ID・source・severity・位置はそのまま出し、独自IDを作らない。
- `src/symbols.ts`：serverの見出し階層を保持し、Outlineへ繋ぐ。構文エラー中は部分・不明扱いで、
  古い見出しを最新として出さない。範囲の推定はしない。
- 全handlerはtrust gateを通す。`diagnosticDebounceMs`設定と`Restart Language Server`を追加した。

## 2026-10-03 全改修レビューの追記

- document通知の解析はURIごとに最新版だけを維持し、編集・close・shutdown時に旧Markdown/MDX解析を取り消す。MDX workerの単一queueへ古いbufferが残り続けない。
- `DocumentSymbol`のrequestはbuffer versionを確認してから返し、server終了・cancel時にclient側のPromiseもsettleする。
- invalidなproject context通知で最後の有効snapshotを消さず、snapshotのprojectIdを照合する。nested workspace folderでは最も具体的なfolderのcontextを選ぶ。
- 明示Build/Inspectで取得したsource route snapshotを拡張からLSPへ渡す。複数front matter schemaが混在する場合はbindingを推測せずsyntax/route contextに限定する。
- 追加したLSP regression testは19件。locationを確定できない診断はProblemsへ0:0の架空rangeで出さず、server logへ説明する。
