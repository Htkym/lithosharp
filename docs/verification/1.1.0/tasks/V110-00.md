## 課題

### 1. B1 は固定SDK 10.0.300 で clean build できない（V110-02 で修復する）

`LithoSharp.Generators` が Microsoft.CodeAnalysis 5.9.0 を参照してビルドされる一方、`global.json` が固定する SDK 10.0.300 のコンパイラは 5.6.0.0 のため、CS9057 で Generator が読み込まれない。その結果 `samples/LithoSharp.DocsSample` で `GeneratedArticles.Entries` / `Binder` が存在せず（CS0117）、`ContentEntryId` の変換（CS1503）も失敗する。`LithoSharp.Tests` は DocsSample を参照するため、テストbaselineもローカルでは取得できない。

- main の CI（run 35297234934、head 324842d）は3 OS とも success。CI は `dotnet-version: 10.0.x` で最新SDKを入れており、.NET 10 の最新SDKは 10.0.401（2026-09-23時点の release metadata）。つまり **CIの成功は固定SDK 10.0.300 での互換性を保証していない**。
- この状態は「対応する最低SDKで Generator が動かない」という V110-02 の Generator host gate そのもの。修復（Roslyn の版を戻す／最低SDKを上げる等）と、その判断根拠が必要。
- B1 の値は B1r で書き換えない。修復後の B1r を別IDで補助計測する。

### 2. パッケージ互換baselineが未整備（V110-02）

`PackageValidationBaselineVersion` は Core の 0.2.0 のみで、`EnablePackageValidation` は `GITHUB_ACTIONS` 条件付きのためローカル pack では動かない。`PublicAPI.*.txt` を持つのは Core・Mdx・Testing の3つで、Generators・Images・Tool・ProjectTemplates には無い。1.0.0 baseline への更新と、package 種別ごとの検査方法の決定が V110-02 の作業。

### 3. MDX テストは worker 依存の導入が前提（V110-01）

新規 worktree では `src/LithoSharp.Mdx/worker/node_modules` が無いため、`npm ci` なしの test は9件が環境要因で落ちる。V110-01 の runner はこの依存導入を前提条件として扱い、失敗を製品不具合と混同しない記録が必要。

### 4. VS Code stable が未導入

ローカルには VS Code Insiders 1.140.0-insider のみ。拡張の対象ビルドと `engines.vscode` の最低版は V110-15 の前に決める必要がある。
