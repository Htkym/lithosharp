## 実装

- `src/preview.ts`：route解決・CSP wrapper・freshness追跡の純粋logic。
  実serve URLのpageをiframe等で表示し、拡張内でMarkdownをHTMLへ変換しない。
  表示URLは検査routeとserved base pathから作り、unknown/draft/未buildは説明を出す。
  拡張子の置換や複数routeの独断選択はしない。
- `src/previewManager.ts`：panel寿命とserver寿命の分離。preview所有のserverは
  最後のpanelと共に止まり、利用者起動のserverはpanel閉鎖で止めない。
  port変更では旧originに残らず張り替える。失敗時は成功結果を明示付きで残す。
- wrapperのCSPはdefault-src none起点で必要範囲に限定し、scriptはnonce、
  frame/connectは所有serverの正確なoriginにする。origin wildcardはない。
  生成siteのscriptは隔離frame内で扱い、VS Code API objectは渡さない。
  messageはorigin・型・URLを検査し、任意command/path実行はない。
- 外部browser遷移は検証済みhttp/https URLに限定する。
- commandはOpen Preview、Refresh、Open in Browser。保存後追従とroute選択までで、
  双方向scroll syncは作らない。未保存・build中・失敗は表示する。
- 全handlerはtrust gateを通す。remote対応可能な層にまとめ、未認定環境は明示する。

## 2026-10-03 全改修レビューの追記

- previewはsource filenameと出力artifact basenameの推測をやめ、CLI inspectの`page.source` / `content.sourcePath` とartifact routeを完全一致で結ぶ。同名ファイルを別folderから誤選択しない。
- Open Previewはserveのstartup eventとinspect結果の両方を待ってからpanelを作る。起動できなかった場合やrouteがない場合は、preview専用で起動したserverを停止する。
- portが変わっても現在のpublic pathを保持し、failed labelには最後に成功したgenerationを表示する。unsaved文書はpanelがlast-saved outputを示していると表示する。
