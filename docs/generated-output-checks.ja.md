# 生成済み出力の検査

[English](generated-output-checks.md)

検査したい成果物に応じてコマンドを選んでください。

| コマンド | 対象 | 実行する処理 |
| --- | --- | --- |
| `check [project]` | 新しく一時生成するサイト | プロジェクトをコンパイルし、ファクトリの実行、生成、検証を行います。 |
| `check-output --output <directory> --base-url <url>` | 既存の配布用ディレクトリ | 再生成せずに、現在のファイルを読み取って検証します。 |

C#スキーマ、型付き参照、コンテンツ読み込みの段階の後に本検査を使ってください。これらの段階では、独自レイアウトやその後のファイル編集によって実際に出力された内容を証明できません。[Docsサンプル](../samples/LithoSharp.DocsSample/README.ja.md#cの型定義から生成物の検査まで)では正常な生成と、生成後の不正なリンクを`LSQ001`で検出する例を分けています。診断の一覧は[サイト品質](site-quality.ja.md)を参照してください。

```powershell
lithosharp check-output --output dist --base-url https://example.com/guide/ --format json
```

ベースURLには実際に公開するHTTPまたはHTTPSのURLを、ベースパスも含めて指定します。
認証情報、クエリ、フラグメントは含められません。相対的な出力パスはコマンドを実行した
作業ディレクトリを基準に解決します。出力形式は`text`、`json`、`sarif`です。
機械可読なレポートは標準出力、検査対象の案内は標準エラー出力に書き出します。
エラー診断がある場合の終了コードは`1`、使い方の誤りは`2`、キャンセルは`130`です。

このコマンドはプロジェクトの検索やコンパイル、ファクトリの呼び出し、ファイルの生成、
出力の修復、レポートファイルの保存、永続キャッシュの読み書きを行いません。
外部URLへのリクエストは`--http`を明示した場合だけ行います。ライブラリからは次のように呼び出せます。

```csharp
var report = await LithoSharp.Quality.GeneratedSiteInspector.InspectAsync(
    outputDirectory, "https://example.com/guide/", cancellationToken);
```

検査器は生成マニフェストを信頼せず、実際のファイルから一覧を作ります。
HTMLとCSSは厳密なUTF-8として読み取り、UTF-8のBOMは有無のどちらも受け付けます。
不正なUTF-8と、UTF-16またはUTF-32のBOMを持つデータは拒否します。文字コードの自動判定はしません。
通常のローカルURL、フラグメント、正規URL、SEO、タイトルの重複、ページへの到達可能性の検査規則を
再利用します。バイナリのリソースは存在だけを検査し、内容をデコードしません。
標準HTMLの即時リダイレクトである`0;url=`のmetaタグについては、ローカルの転送先、
転送先の欠落、循環、連鎖、正規URLとの一致を検査します。対応していないrefreshの形式は
エラーになります。JavaScriptによるリダイレクトは検査対象外です。

既存のディレクトリには信頼できるビルドグラフやソースのスナップショットがありません。
そのため、現在のソースや設定に出力が一致すること、意図したすべてのページが生成されたこと、
アセットが登録済みか未使用かということ（`LSQ008`）は、この検査では確認できません。
ローカルの検査はアセットの間接的な所有関係を推定せず、外部HTTP応答へのリクエストも行いません。
後述する任意の`--http`処理で、公開先の応答を別に確認します。
これらのビルド時の関係を確認する必要がある場合は、生成時の品質検査を使ってください。

検査中は選択したディレクトリとその配下を変更しないでください。配下、選択したルート、
その親ディレクトリにあるリンクと再解析ポイントは拒否します。ルートの衝突や曖昧なパス、
Unixのファイル名に含まれる区切り文字ではないバックスラッシュも拒否します。
一覧に含めるのは通常のファイルとディレクトリだけです。Unixではファイルを開く前に種別を検査し、
FIFO、ソケット、デバイスを拒否します。この検査にはLinuxの`statx`またはmacOS x64/arm64の
`lstat`が必要です。ネイティブの検査を利用できない場合は、検査全体が失敗します。
テキストの読み取り前に、ファイルハンドルが対象内に収まることを検証します。
結果を返す前に、ファイル一覧と検査したテキストのハッシュを再確認します。
これは変更の検出であり、同時に悪意のある変更が行われる状況での不可分なスナップショットを
保証するものではありません。

配布用の出力を検査するためだけの再生成を避けるには、ビルド時に`SiteGenerationOptions.Quality`を
有効にするか、そのビルドの出力に`check-output`を実行します。`check-output`は実行するたびに
現在のバイト列を読み取り、入力や出力が変わった後に以前の成功を再利用することはありません。
ソースや設定を変更した場合は、出力が最新かどうかを判断する前に、配布用の出力を再ビルドしてください。

## 公開後の明示的なHTTP検査

公開後は既存のコマンドに`--http`を付けてHTTP応答を確認できます。

```powershell
lithosharp check-output --output dist --base-url https://example.com/guide/ --http --format json
```

この公開先HTTP検査を実行するのは`--http`を明示したときだけです。通常のビルドでは実行しません。
HTTP検査を始める前に、既存の公開検査器で現在の実ファイル一覧を検証します。
出力の生成、サイトプロジェクトの実行、キャッシュの保存、公開済み基準の作成や昇格は行いません。
任意の`--baseline`比較は別の検査です。基準の初期作成を明示するオプションと`--http`を組み合わせた場合は、
両方の検査が成功したときだけ基準を作成します。

実際のGETリクエストで次の項目を確認します。

- 現在のHTMLのURLとディレクトリ索引の別名URLが、`text/html`で応答すること。`404.html`自体の応答は200または404を許容し、未知URLへの404応答は別に検査します。
- MarkdownのURLが`text/markdown; charset=utf-8`で応答し、本文が有効なUTF-8で、検査したローカル成果物とハッシュが一致すること。
- 現在のllms.txtやsitemap.xmlが存在する場合、そのMIMEが正しいこと。
- HTTPリダイレクトが選択したオリジン内に留まり、検査した一覧にある別名URLや、標準HTMLのリダイレクト先に従うこと。
- サイトのベースパス配下に作る一意の未知URLが、直接HTTP 404を返すこと。成功応答の代替ページやリダイレクトはHTTP 404として扱いません。
- サブパスのサイトでも、実際のオリジンの`/robots.txt`を確認すること。`project/robots.txt`をオリジンのルート管理とみなしません。

選択したルートサイトの検査済み出力にrobots.txtがある場合、公開先の応答はその成果物のUTF-8バイト列と
一致する必要があります。オリジンのルートにあるrobotsが外部管理か無効の場合は、観測した応答を別に報告します。
404応答は、その外部リソースが存在しないという報告であり、robotsファイルを生成できた証拠にはなりません。
検査器は既存のクローラー方針やホスト設定を変更しません。

リクエストには既存の公開アドレス専用の通信処理とDNS検査を使います。Cookieやプロキシの認証情報は使いません。
リクエスト間隔の下限は500 ms、各確認のタイムアウトは10秒とし、リダイレクトの追跡回数にも上限があります。
別オリジンやプライベートアドレスへのリダイレクトは拒否します。localhostやプライベートネットワークのサーバーは
この公開先検査の対象外なので、ローカル配信の手順で確認してください。
デコード後のMarkdown本文の上限は16 MiB、robotsの上限は512 KiBです。以前のHTTP判定をキャッシュしません。

`LSPHTTP001`は成果物のHTTP応答、MIME、本文の不一致、`LSPHTTP002`は観測したリダイレクト、
`LSPHTTP003`は未知URLのHTTP 404検査の失敗、`LSPHTTP004`はオリジンのルートにあるrobotsの観測や失敗を示します。
`LSPHTTP000`は明示的に依頼した範囲の検査が完了したことを記録します。エラー診断があれば終了コードは`1`です。
完了というメッセージは、すべての検査が成功したという意味ではありません。

この処理はHTTPの観測であり、ブラウザーを実行するものではありません。JavaScriptやHTMLのmeta refreshによる移動、
ホスト固有のLinkやVaryヘッダー、コンテンツネゴシエーション、リッチリザルトの条件、外部スキャナーの得点は確認しません。
必要な項目は別に調べてください。生成物の検査に成功しただけではこのHTTP検査を実行したことにはなりません。
