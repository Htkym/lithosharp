# 生成済み出力の検査

[English](generated-output-checks.md)

検査したい成果物に応じてコマンドを選んでください。

| コマンド | 対象 | 実行する処理 |
| --- | --- | --- |
| `check [project]` | 新しく一時生成するサイト | プロジェクトをコンパイルし、ファクトリの実行、生成、検証を行います。 |
| `check-output --output <directory> --base-url <url>` | 既存の配布用ディレクトリ | 再生成せずに、現在のファイルを読み取って検証します。 |

```powershell
lithosharp check-output --output dist --base-url https://example.com/guide/ --format json
```

ベースURLには実際に公開するHTTPまたはHTTPSのURLを、ベースパスも含めて指定します。
認証情報、クエリ、フラグメントは含められません。相対的な出力パスはコマンドを実行した
作業ディレクトリを基準に解決します。出力形式は`text`、`json`、`sarif`です。
機械可読なレポートは標準出力、検査対象の案内は標準エラー出力に書き出します。
エラー診断がある場合の終了コードは`1`、使い方の誤りは`2`、キャンセルは`130`です。

このコマンドはプロジェクトの検索やコンパイル、ファクトリの呼び出し、ファイルの生成、
出力の修復、レポートファイルの保存、永続キャッシュの読み書きを行いません。
外部URLへのリクエストも行いません。ライブラリからは次のように呼び出せます。

```csharp
var report = await LithoSharp.Quality.GeneratedSiteInspector.InspectAsync(
    outputDirectory, "https://example.com/guide/", cancellationToken);
```

検査器は生成マニフェストを信頼せず、実際のファイルから一覧を作ります。
HTMLとCSSは厳密なUTF-8として読み取り、UTF-8のBOMは有無のどちらも受け付けます。
不正なUTF-8と、UTF-16またはUTF-32のBOMを持つデータは拒否します。文字コードの自動判定はしません。
通常のローカルURL、フラグメント、正規URL、SEO、タイトルの重複、ページへの到達可能性の検査規則を
再利用します。バイナリのリソースは存在だけを検査し、内容をデコードしません。
標準HTMLの即時リダイレクトである`0;url=`のmetaタグについては、ローカルの転送先、
転送先の欠落、循環、連鎖、正規URLとの一致を検査します。対応していないrefreshの形式は
エラーになります。JavaScriptによるリダイレクトは検査対象外です。

既存のディレクトリには信頼できるビルドグラフやソースのスナップショットがありません。
そのため、現在のソースや設定に出力が一致すること、意図したすべてのページが生成されたこと、
アセットが登録済みか未使用かということ（`LSQ008`）は、この検査では確認できません。
アセットの間接的な所有関係を推定したり、外部HTTP応答を検査したりすることもありません。
これらのビルド時の関係を確認する必要がある場合は、生成時の品質検査を使ってください。

検査中は選択したディレクトリとその配下を変更しないでください。配下、選択したルート、
その親ディレクトリにあるリンクと再解析ポイントは拒否します。ルートの衝突や曖昧なパスも対象です。
Unixのファイル名に含まれる、区切り文字ではないバックスラッシュも拒否します。
一覧に含めるのは通常のファイルとディレクトリだけです。Unixではファイルを開く前に種別を検査し、
FIFO、ソケット、デバイスを拒否します。この検査にはLinuxの`statx`またはmacOS x64/arm64の
`lstat`が必要です。ネイティブの検査を利用できない場合は、検査全体が失敗します。
テキストの読み取り前に、ファイルハンドルが対象内に収まることを検証します。
結果を返す前に、ファイル一覧と検査したテキストのハッシュを再確認します。
これは変更の検出であり、同時に悪意のある変更が行われる状況での不可分なスナップショットを
保証するものではありません。

配布用の出力を検査するためだけの再生成を避けるには、ビルド時に`SiteGenerationOptions.Quality`を
有効にするか、そのビルドの出力に`check-output`を実行します。`check-output`は実行するたびに
現在のバイト列を読み取り、入力や出力が変わった後に、以前の成功を再利用することはありません。
ソースや設定を変更した場合は、出力が最新かどうかを判断する前に、配布用の出力を再ビルドしてください。
