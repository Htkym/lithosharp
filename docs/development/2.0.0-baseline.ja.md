## 許可する変更と維持する契約

許可するmajor変更は、次の公開DOMの撤去です。
`LithoSharp.Testing.SiteTestDocument.Document.get -> AngleSharp.Dom.IDocument`

snapshot/query/Assertへの移行、unsupported selector、DOM mutationへの対応は、
後続taskで実装と説明を行います。J-00ではAPIを削除しません。

- その他の既存public APIと、`LSM` / `LSG` / `LSQ`のIDを維持します。
- `LSG005` / `LSG006`と同じschema診断を重複して追加しません。
- Generatorの`netstandard2.0`、Roslyn 4.14、YamlDotNetのpackとhost互換性を維持します。
- severityや位置の変更も後続の互換表に記録し、未記録の破壊変更は許可しません。
- SharpDepsの旧report v2、旧provider、command/settings、Quick/Semantic/trustを維持します。

Coreの`PackageValidationBaselineVersion`は現値`1.0.0`を保持します。
公開`1.1.0` nupkgとallowlistを用意した後続taskで更新候補を検証します。
現行versionや開発対象versionに合わせた機械置換は行いません。

## 共有Markdownの所属と保留事項

共有Markdownは、LithoSharp内で独立parse-only部品を作り、独立NuGet/runtimeと固定版source供給の候補を用意します。
両repoとGenerator/Analyzerで同版利用を確認してから、安定公開前に別repoへ移管します。
移管時もpackage名、API、contractを維持します。
HTML描画、site facts/rules、HTML bridgeはLithoSharpに置きます。
Markdownからgraphへの変換、SQLite、Query、clientはSharpDepsに置きます。

共有部品のTFM、固定版sourceの供給方式と正式IDは、ここでは確定しません。
UTF-16原文位置/SourceSegments、identity/full-text hash/SemanticHash/cache、
public DTO/ParserVersion/ContractVersionの契約決定はJ-01で扱います。
J-00では別repoの作成、コード抽出、実装を行いません。

## taskの完了手順と停止条件

文書の保存と差分確認の後、J-00の差分だけをcommitし、作業branchへpushします。
commit SHAとremote到達は、Git履歴とタスクの実行記録で追跡します。

進行順は、task commit/push → Bocchi review → 次taskです。
このJ-00記録の作成時点ではBocchi review待ちです。未通過や未解決の指摘がある間は停止し、
J-01/MD-01の契約決定、コード抽出、実装を開始しません。
review通過後の次taskはJ-01です。
mainへのpush、merge、releaseは承認されていません。
