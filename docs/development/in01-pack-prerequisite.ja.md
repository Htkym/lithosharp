# IN-01に先行する最小pack統合

基準はfeature/2.0.0の7d3454e8a1034d94bb984db447b625380bb60c60です。既存CIはCore1.1.0から非packableのMarkdown開発project1.0.0への依存をnuspecへ出し、版照合で拒否していました。固定artifactを使う最小pack前提を先行させ、CI成功後にIN-01の4 host検証へ進みます。RA-01やIN-01の合格を先取りする変更ではありません。

CoreはLithoSharp.Markdown [2.0.0-preview.1]を参照します。MD-05で固定したruntime/source pairのbytesをeng/markdown/feedへそのままコピーし、repoのNuGet.Configでこの2 IDだけを専用feedへ割り当てました。両CI入口はrestore前にpairのhash、manifest、HEADのGit blobとcanonical parser/sourceの対応を検査します。現在の作業ツリーのPortable sourceをCoreへCompileリンクする代替は使いません。既存pairの再pack、上書き、版変更はありません。

runtimeのSHA-256は554a4c71de4fb8c55872895a985cf8f66e9518346e451e91a2607d69d17fb8ed、sourceは537bd22998e5a2560a8cffea2f829b3bfae79179b91572671fbf66d0a46d9a06です。runtime DLLは1208ca8b32332ef58ea68838a6c672e3ea760257f84728e0a7e20b353d8389a5です。対応するsource commit、canonical hash、parser、contract、profile、licenseについてはdocs/development/md05-artifact-pair.jsonを参照します。

validatorはMarkdownの独立版とLICENSEファイルを明示的に扱い、exact版、nupkg/DLL hash、source/contract対応、YamlDotNet [18.1.0]を検査します。Analyzer packageが自身のcompiler payloadとXMLを含み、runtime dependencyや予期しないDLLを含まないことを検査します。旧7 packageの版照合、archive path、metadata、redistribution notice、Core symbolsの検査は保持しました。

template fixture feedへ固定runtimeを追加し、Markdownだけにcomponent版を要求します。package-only serveも同じ版を照合します。consumer compatibilityは固定componentの供給元を追加し、復元したnupkg/DLLのbytesを検査します。配布用の旧7 package feedとsecurity gateの正確な集合は保持し、componentは専用feedに分けました。consumer compatibilityの既存baseline binary、Core DLLだけの置換、source再compile、同一出力の条件は変更していません。

変更した13 lockでは既存packageの版・contentHashを保持しました。単一workerの更新restoreは1.757秒、locked restoreは1.679秒で成功しました。RTK経由のCore Release buildは4.371秒、エラー・警告0でした。Coreだけのpackage validation付きpackは1.593秒で成功し、実際のCore packageと未変更のRA-01 Analyzer候補を新validatorで確認しました。

現行Core1.1.0がpreview componentへ依存するため、packにNU5104警告が1件あります。警告は抑制していません。このCore packageはCI接続を検証するローカル候補です。公開用の版更新と判断は後段で行います。publish workflow、tag、NuGet公開は変更・実行していません。

Generator/Analyzerのsource選択は変更せず、SharpDepsの実装も変更していません。4 hostの実行・事実投影の一致はIN-01の残作業です。remote CI全体が同じSHAで成功するまで次段階完了とはせず、MD-06はIN-01 PASS待ちを維持します。pushは朝のユーザー対応待ちです。

既存consumer compatibilityは、SiteRouteとSlugHelperの長期安定APIを使うfixtureです。このfixtureのbinary/source経路は11.009秒でPASSし、Core DLLだけの置換後も同一出力でした。新runtimeのMarkdown APIを使う任意の1.x consumer全体のbinary互換まで証明した結果ではありません。

限定controlでは、固定artifactのbytes改変、誤ったMarkdown pin、HEADへの日本語名parser source追加、未宣言のcomponent Compile sourceをそれぞれ拒否しました。package-only canaryでCoreの実ParseMarkdownAsyncを実行し、実ロードruntime DLLの固定SHA、parser identity、YamlDotNetのassembly名と情報版18.1.0を確認しました。4 host全体の一致を先取りした結果ではありません。
